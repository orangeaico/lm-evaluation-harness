# Repo-Eval Tasks

This directory contains LLM evaluation tasks for repository-level code understanding, focusing on component location and code identification within Python codebases.

## Tasks

### DefinedIn (`repo_eval_defined_in`)

**Description**: Given a repository name, component name and type (class/function/method), identify where it's defined in the codebase.

**Input Format**:
- Repository name (e.g., "pydata/xarray")
- Component name (e.g., "DataArray")
- Component type ("class", "function", or "method")

**Output Format**: JSON with:
```json
{
  "filename": "file.py",
  "class": "ClassName or null"
}
```

**Metrics**:
- `defined_in_exact_match`: Both filename and class must match exactly
- `defined_in_partial_match`: Only filename must match

### BelongsTo (`repo_eval_belongs_to`)

**Description**: Given a repository name and code chunk, identify which file and component it belongs to.

**Input Format**:
- Repository name (e.g., "pydata/xarray")
- Code snippet (30% of original source)

**Output Format**: JSON with:
```json
{
  "filename": "file.py",
  "class": "ClassName or null",
  "method": "method_name or function_name or null"
}
```

**Metrics**:
- `belongs_to_exact_match`: All three fields must match exactly
- `belongs_to_partial_match`: Only filename must match

## Usage

### Individual Tasks
```bash
# Run DefinedIn task only
lm_eval --model hf --model_args pretrained=<model_name> --tasks repo_eval_defined_in

# Run BelongsTo task only
lm_eval --model hf --model_args pretrained=<model_name> --tasks repo_eval_belongs_to
```

### All Tasks
```bash
# Run all repo-eval tasks
lm_eval --model hf --model_args pretrained=<model_name> --tasks repo_eval
```

## Data Source

Tasks load data from locally generated JSONL files:
- `data/tasks/*/*/DefinedIn.jsonl`
- `data/tasks/*/*/BelongsTo.jsonl`

These files are generated by the repo-eval task generation pipeline from Python repositories and contain self-sufficient prompts ready for LLM evaluation.

## Task Properties

- **Zero-shot evaluation**: No few-shot examples (num_fewshot: 0) to prevent confusing instruction loops
- **Repository context**: Tasks include repository name for better model understanding
- **Generative format**: Models generate JSON responses
- **JSON validation**: Responses are parsed and validated as JSON
- **Comprehensive scope**: Includes classes, functions, async functions, AND methods
- **Duplicate filtering**: Components appearing in multiple files are excluded for clarity
- **Simplified outputs**: Filename-only paths instead of complex absolute paths
- **Difficulty levels**: Tasks are categorized as easy/medium/hard

## Dataset Coverage

Current tasks are generated from:
- **xarray**: Scientific computing library
- **Commits**: Multiple commits from SWE-bench_Verified dataset
- **Components**: Classes, functions, async functions, AND methods (comprehensive coverage)
- **Unique components**: Only components with unique names across the codebase
